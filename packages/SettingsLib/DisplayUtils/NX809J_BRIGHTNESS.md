# NX809J calibrated manual brightness

The NX809J panel's backlight control is nonlinear. Applying the existing HLG
conversion directly to that control compresses the lower half of the manual
slider. This port applies HLG to calibrated light output instead:

```text
targetNits = F(min) + HLG(sliderFraction) * (F(max) - F(min))
backlight = inverseF(targetNits)
```

`F` uses the factory's strictly increasing 52-point `screenBrightnessMap`, with
piecewise-linear interpolation in both directions. The reverse slider mapping
uses the same table and inverse HLG. Both conversions use the supplied bounds,
so changes to the allowed brightness range preserve its endpoints.

The calibration applies only when `ro.product.device` is `NX809J`, the display
unique ID is `local:4630947168392018835`, and the bounds are normalized and valid.
SystemUI's legacy controller and newer interactor both pass their display ID.
Existing three-argument float calls use the default display. Other displays and
legacy integer brightness conversions retain the existing HLG path.

The NX809J default remains linear backlight, matching the tested gamma-disabled
mode. The existing property selects either mode:

| `sys.brightness.disable_gamma_conversion` | Mode |
| --- | --- |
| `true` | Linear backlight interpolation |
| `false` | HLG in calibrated nits, followed by inverse panel interpolation |

The property is read when the process initializes. Restart SystemUI after changing
it. This property does not persist across a phone reboot; NX809J then defaults to
linear mode. This change does not add a settings toggle or modify automatic lux
mapping, panel drivers, or vendor display configuration.

## Calibration provenance

The table was extracted from the user's existing NX809J RedMagicOS 11.0.21MR1
Android 16 backup, built on 2026-01-30. Its 52 points match the active panel table
in the AviumUI port. Source file:

```text
vendor/etc/displayconfig/display_id_4630947168392018835.xml
SHA256: 6fbb9628da623f0445c631a2e7ac8be19b77bd393db8aeb52b099540c540c4a9
```

`NitsBrightnessCurve.java` retains the source data's copyright and license
notices. The table is generated by the NX809J portable-build tooling; this fork
consumes the checked-in output directly. The nits values are a calibration model,
not new photometer measurements.

## Validation

Run the standalone host checks with Python 3 and Java 17 or newer:

```bash
python3 packages/SettingsLib/DisplayUtils/tests/host/run_tests.py \
    --jdk-bin "$ANDROID_BUILD_TOP/prebuilts/jdk/jdk21/linux-x86/bin"
```

The checks compile the production conversion classes. The Android classes under
`tests/host/android` provide only host substitutes for platform dependencies.
Five device/property configurations exercise all 65,536 slider positions in four
brightness ranges, checking monotonicity, bounds, inverse positioning, external
display fallback, defaults, and the legacy integer conversion.

The change passed an incremental SystemUI build in the existing NX809J AviumUI
16.2 port tree. The signed SystemUI update was applied on the device; both modes
started successfully and a read-only probe of the same compiled module passed.
For the recorded manual range `0..0.8584`, the new curve's midpoint is about
`0.27948` backlight / `57.05` calibrated nits, compared with about `0.07153`
backlight for the old HLG mapping. Visual acceptance, long-duration use, HBM and
external-display device testing remain outstanding. A full ROM build from this
fork has not been performed.
